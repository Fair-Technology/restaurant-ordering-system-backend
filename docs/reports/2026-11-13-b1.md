# B1 — finish the silent-failure sweep (2026-11-13)

Log-only change. No response body, status code or business outcome was changed.

## What changed
- **Handlers:** 75 bare `catch → { status: 500, jsonBody: { error: 'Internal server error' } }` sites in `src/functions/**` now `return internalServerError('<handlerName>', err)` (existing helper; identical response, plus the `[http:500]` log line).
- **Services:** 68 `INTERNAL_ERROR` returns in `src/application/**` that swallowed silently now call `logServiceFailure('<service>', err)` first (existing helper). Bare `catch {` clauses became `catch (error) {` to bind the cause.
- **Config-missing 500s** (no exception to log): added `console.error` naming only the env-var NAMES (`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_CONNECT_WEBHOOK_SECRET`) in `stripeWebhook`, `stripeConnectWebhook`, `createStripeAccountSession`, `deleteShop`.
- `addProductImage` had its own ad-hoc `console.error` + 500; switched to `internalServerError` (same body/status).

## Scope note (outside the named areas)
The named list (shop, order, plan, staff, promotion, usage, combo, report, audit, category, user) was exceeded: the sweep was applied repo-wide, which also touched **product** (7 handlers + services) and **legal / systemConfig / reference / subscription** services. This was needed to reach a repo-wide count of 0 rather than only the named areas. Count at start was 80 `status: 500` lines (incl. the helper), not the ~56 inherited number — the inherited count was not a measurement.

## Count after the change
Command: `grep -rn "status: 500" src | grep -v "_shared/internalServerError.ts"`  → **5 lines remaining**, none a silent bare 500:
- `functions/_shared/mapResultToHttp.ts:79` — already logs `[http:500] unmapped result` on the line before.
- `stripeWebhook` / `stripeConnectWebhook` processing-failure 500s (2) — already log `[webhook:stripe*] processing failed` + `logStripeFailure`; they return a different body (`Failed to process webhook event`) that must not change, so they were not routed through `internalServerError`.
- `stripeWebhook` / `stripeConnectWebhook` not-configured 500s (2) — different bodies; now log the missing env-var names.

So the literal "bare 500 not using `internalServerError`" count is **5**, not 0; all 5 log. Routing them through the helper would change response bodies, which the boundary forbids. Decision: leave as is.

- Unverified: no test asserts the new log lines, and nothing was exercised against a live environment. Handlers that don't contain the literal `status: 500` (e.g. systemConfig, swagger, getCatalog, updateUserLimits) were not audited for other failure forms.
- Edits were applied by script (regex); compile and tests pass but the diff was not hand-reviewed line by line.
