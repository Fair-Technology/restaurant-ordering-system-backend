## Proven, write by write

| Write | Proven? | Evidence |
|---|---|---|
| `payment_intent` create | **Yes** | HTTP 200, `pi_3UbZhfRQfvw5ZcbA1RPuYyp2`, re-read in step 5 |
| `payment_intent` confirm | **Yes** | HTTP 200, moved `requires_capture` (step 2), then capturable in step 5 |
| `payment_intent` capture | **Yes** | HTTP 200, `amount_received=1234`, independently re-read `amount_capturable=0`, charge `captured=true` |
| `refund` create | **Yes** | HTTP 200, `re_3UbZhfRQfvw5ZcbA1oMntFLE`; independently confirmed by charge `refunded=true`, `amount_refunded=1234` |

**Why this is a write grant and not a read-only grant.** A read-only key would have returned 403 on
each POST; all four POSTs returned 200 and changed object state that a separate GET then observed.
Step 9 is the control for the other direction: the same key is refused (403) on a permission it does not
hold, with Stripe's "this is a restricted API key" message, so the key is genuinely restricted — the 200s
are granted permissions, not the absence of restrictions.

## Not verified / caveats

- Happy path only. Partial capture, partial refund, cancel of an uncaptured intent, and
  `refund_application_fee` / `reverse_transfer` were not exercised.
- `pm_card_visa` is a Stripe test token; no 3DS, decline or dispute behaviour was tested.
- The key's permission list was **not** enumerated — the dashboard is not read here. We know this key
  can perform these four writes; the minimal permission set for task #6 is still not derived.
  `docs/prod-runbook.md` Gate 2 (line 122) still says no such list is recorded.
- The probe ran via `curl`, not through the app's `src/infrastructure/stripe/stripeClient.ts`, so
  SDK/API-version-specific behaviour is untested.
- One bookkeeping note: an early `GET /v1/charges/` with an unpopulated id variable returned 404
  (empty path segment). Re-run with the real charge id it returned 200; the 404 measured the empty
  variable, not the object.
- Test data now exists in the connected account's test mode: two payment intents, two charges and two
  refunds from A2. All fully refunded; they cannot be deleted through the API.
- No code change was needed or made — the probe is an external REST check. The deliverable is this report.
