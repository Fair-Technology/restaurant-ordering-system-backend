## Genuine open gap (the only thing this audit still justifies building)

| # | Gap | Evidence of absence |
|---|---|---|
| G2 | **`noindex` on storefronts (and admin/superadmin) + link-preview meta injected by a Function.** Audit "Platform plumbing". | `grep -rin "noindex\|robots\|og:\|openGraph"` over all `.ts/.tsx/.html` (excl. `node_modules`) → 0 hits. `rs-storefront/index.html` carries only charset/viewport/title. Confirmed separately by @frontend-engineer-1. |

**Scope note — rev 3 (the failure mode this packet exists to avoid).** The storefront
is a Vite SPA. A **client hook alone cannot satisfy link previews**: WhatsApp/Telegram/
Slack/Twitter unfurls do not execute JavaScript, so helmet-style injection hands the
crawler an empty `<head>` and the card still renders as a grey box while every browser
test passes. Spec §14 (`spec.md:1309-1312`) fixes the mechanism: the card is *"injected
into the storefront's HTML shell by a small Function."* So G2 splits into:

- **Static half (trivial, any wave):** `noindex` + `robots.txt` on admin/superadmin —
  plain files in each app's `public/` (none has a `robots.txt` today) and the SWA
  `navigationFallback.exclude` already passes `/*.txt` through (`staticwebapp.config.json`).
- **Dynamic half (real work, backend + storefront):** a Function serving `/shops/<slug>`'s
  HTML with `<title>`, `<meta name="description">` and `og:*`. **Two consumers, both
  required:** the crawler (server, Function) *and* the browser tab (client hook — the SPA
  routes client-side, so without a title sync the tab shows the wrong shop). Dropping
  either half is the mirror-image bug.
- **Unresolved — the packet's first decision, not a detail:** the Function has **no home**
  today. `rs-storefront/api` does not exist and the SPA calls the backend cross-origin by
  absolute URL (`baseApi.ts:4`), so an SWA internal rewrite cannot point at the external
  Functions host. The packet must pick: an SWA-managed function in `rs-storefront/api`
  reached at `/api/*`, or linking the existing backend Functions app as the SWA's API.
  Left unstated, a worker stalls on this mid-wave.
- **`og:image` needs an ordered fallback:** `heroImageUrl → logoUrl → static brand card`
  — both branding images are nullable and `showHero` can be off.
- **Keep storefront `noindex` out of `index.html`:** `/` is the restaurant list and
  `/shops/:slug` is the shop (both served from `index.html`), so a static tag de-indexes
  the root too. Storefront `noindex` is per-route, via the Function.

Ownership: Function + meta contract → backend (@backend-engineer); static half + client
title hook → frontend (@frontend-engineer-1).

## Appendix — G2 acceptance test spec (draft for the wave-6 packet)

Written against the meta contract agreed in-thread. This is the assertion set; the packet
should carry it verbatim so the pass condition is not "green in the browser".

**Runner:** the crawler-facing checks (T1–T6 below) run against the **deployed dev
storefront**, wired into `rs-e2e/.github/workflows/contract.yml`. **Placement corrected by
A3's finding (`docs/reports/2026-11-13-a3.md`): the `contract` job, not the browser
`customer` job** — the customer job failed on 2026-11-11 at `playwright install --with-deps
chromium`, which skipped its own curl and tests, so a chromium flake would silently take
down unfurl monitoring. G2's assertions are browserless (raw-HTML + anonymous `og:image`
fetch), so they belong in the API-only `contract` job or a plain `curl` step **before** the
install. `CUSTOMER_URL` is already defined there and is not a secret. **Fail, never skip:**
a missing `og:`/`robots` tag is a FAIL, not a skip, or the run decays to green while
grey-boxing. Cron runs only from the default branch, and GitHub disables it after 60 days of
inactivity — so monitoring exists only once the packet's PR lands on `main`. **A3 confirmed
the cron fires** (3 scheduled runs), so the conduit is live; note it lands ~8h after its
declared 06:17 UTC slot, so don't expect a precise window.

**Verified route surface** (`rs-storefront/src/App.tsx:17-27`) — five public paths hang off
the storefront, not one, and the route rule must cover `/shops/*` and `/legal/*`:

| Route | Component | Carries |
|---|---|---|
| `/` | `HomePage` | sales site |
| `/shops/:slug` | `ShopView` | shop landing |
| `/shops/:slug/checkout` | `CheckoutPage` | — |
| `/shops/:slug/orders/:orderId` | `CustomerOrderPage` | **`?t=<accessToken>`** |
| `/shops/:slug/legal/:doc` | `LegalPage` | — |
| `/legal/sub-processors` | `SubProcessorsPage` | — (**no slug** — frontend's list omitted it) |

The order page's URL embeds the session token in the query string
(`CheckoutPage.tsx:55` `orderPath` → `/shops/${slug}/orders/${orderId}?t=${accessToken}`).
If the route rule is `/shops/:slug` **exactly**, that URL falls through
`navigationFallback` to the plain shell with no `robots` meta and the token URL becomes
indexable and shareable — spec §16's blanket "storefronts carry `noindex`" (`spec.md:1309`)
would hold only for the landing page. **The rule must be `/shops/*` and `/legal/*`.**

| T10 | `/shops/<slug>` headers | — | — | assert **`Cache-Control` is present** on the per-shop meta response (unauthenticated + crawler-facing; the hop re-runs the full public DTO incl. an order-limit read, `executeGetShopBySlug.ts:44`, so a miss per unfurl and per cold load is an RU cost and a DoS surface). Caching is **two-lifetime**: shell **per-origin**, meta **per-shop** — a per-shop cache of the whole injected document refetches the shell once per shop. Then **cross-slug non-collision:** warm slugA, immediately GET slugB, assert B's card is not A's — a naive shared cache key fails T2 intermittently, not deterministically |
| T11 | shell source integrity | — | — | extract **both** the `<script src>` and the CSS `<link href>` from the **served** `/shops/<slug>` HTML and GET each → **200** (`text/javascript` / `text/css`). The deployed shell references content-hashed assets (today `/assets/index-ty0qzupJ.js` verified 200, `index-DtpFGWsF.css`). **Catches the baked-copy trap:** if the Function serves a build-time copy of the shell, its hashes go stale on the next storefront deploy — the card unfurls perfectly and the human gets a **white/unstyled page**, and neither the raw-HTML check nor the browser-DOM test notices, because both assert meta, not that the referenced assets resolve. This is why the Function must **fetch-and-inject the current shell**, not bundle one. It also widens "ship and revert as one unit": with a baked copy, *every* storefront deploy is a staleness risk |

**Coverage note.** T1–T8 are happy-path raw-HTML checks and are exactly what a broken
implementation can pass; T9 (fail-open) and T10 (cache correctness) are the two behaviours
**no happy-path assertion covers**, so both belong in the packet or the feature ships with
a silent outage mode and a cross-shop card-collision mode that every other test passes.

**Contract invariants the Function must hold** (from @backend-engineer): `og:title` = shop
name; `og:description` = `name` + `city` (fallback string when `address.city` is absent);
`og:image` = absolute `https` from `branding` (hero→logo→static), `og:type=website`;
