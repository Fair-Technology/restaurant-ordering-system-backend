## 4. Failure signature (what "config-vs-reality gap" looks like)

In Application Insights (query from `docs/prod-runbook.md`, "Alert: Stripe permission or configuration failure"):

```kusto
traces
| where message contains "[stripe:failure]" or message contains "[alert:platform]"
| where timestamp > ago(30m)
| project timestamp, message
```

- **Pass:** zero `[stripe:failure]` and zero `[alert:platform]` lines in the window; order reaches `ACCEPTED`; PI `succeeded`.
- **Fail:** `[alert:platform] kind=stripe_permission_or_config` with `more_permissions_required` / `status=403` means a permission is missing. Put the `op=` and `requestId` in the ticket (not the key), add the permission to the Stripe key, and re-run O1–O4. `status=401` means the wrong or revoked key.
- Expected, not a failure: the wallet-domain skip log ("STRIPE_SECRET_KEY is a restricted key…", `registerStorefrontDomain.ts`). Stripe refuses payment-method-domain calls for restricted keys by design (runbook §7.6), so Apple/Google Pay need dashboard registration.
