# D3 — Backups with a tested restore (2026-11-13)

## Result in one paragraph
Backup configuration and a restore script are written, and **one restore was actually practised**. It was
**not** production data and **not** dev data: it was synthetic documents (50 orders, 50 invoices), exported
from a scratch database and restored into a second scratch database, both on a **local Cosmos emulator
container** (`rs-d3-scratch-cosmos`, `http://localhost:18081`). No Azure or Cosmos resource was created,
changed or read. Real-data restore from the live account, and the Azure-side parts, are **unverified** (below).

## What was written
| File | Purpose |
|---|---|
| `scripts/backup/archiveLib.ts` | Export `orders` + `invoices` to JSONL with a manifest (count + SHA-256 per file); verify an archive; restore it; scratch-target guard |
| `scripts/backup/export.ts` | CLI, **read-only**. Env names: `COSMOS_DB_ENDPOINT`, `COSMOS_DB_KEY`, `COSMOS_DB_DATABASE_ID` |
| `scripts/backup/restore.ts` | CLI restore. Env names: `RESTORE_COSMOS_ENDPOINT`, `RESTORE_COSMOS_KEY`, `RESTORE_COSMOS_DATABASE_ID` |
| `scripts/backup/seedScratchSource.ts` | Drill helper; local emulator only |
| `infra/main.bicep` | Cosmos `Continuous30Days` made explicit; private `records-archive` blob container with an 8-year (2922-day) time-based retention policy, **unlocked** |
| `test/scripts/backupArchive.test.ts` | Guard accepts localhost / `*-restore-test`, refuses the dev and prod accounts; tampered archive is detected |

Safety properties of the restore script: it refuses any endpoint that is not `localhost`/`127.0.0.1` or a
`*-restore-test` account (so it cannot write to the dev or prod account); it uses `RESTORE_*` variable names so a
shell configured for the app cannot become a target; it checks every file against the manifest checksum and count
**before** writing; it upserts (idempotent) and never deletes.

## Practised restore (actual output)
Source `d3-source` → archive in `/tmp` → target `d3-restore-scratch`, same emulator.

```
seeded 50 synthetic documents into each of orders, invoices
# export (COSMOS_DB_DATABASE_ID=d3-source)
orders: 50 documents, sha256 2381416c12e03f201c7aa79effc4ba8615a13286992c4bc645f2fade97b7e506
invoices: 50 documents, sha256 5bb5c10b0f92d041ae874e7730da6dfdd06e785b133daee063a01e5d11442f43
# restore (RESTORE_COSMOS_ENDPOINT=http://localhost:18081, RESTORE_COSMOS_DATABASE_ID=d3-restore-scratch)
npx ts-node --transpile-only scripts/backup/restore.ts /tmp/d3/archive
orders: expected 50, restored 50, counted in target 50 OK
invoices: expected 50, restored 50, counted in target 50 OK
```
Restored count: **100 documents (50 + 50)**, counted with `SELECT VALUE COUNT(1)` in the target, not inferred
from the script's own counter. I also re-exported the target and compared every document field-by-field
(ignoring `_rid/_ts/_etag`): identical for both containers. The emulator key used is the public, well-known
emulator key; no real secret was used or printed.

## What is NOT verified
- **No real data was restored.** I had no dev/prod credentials in this worktree and Azure/Cosmos are read-only
  for agents, so the counts above say nothing about the size or shape of real orders/invoices.
- **The Cosmos point-in-time restore (`az cosmosdb restore`)** in `docs/prod-runbook.md` §11 was **not run**; it
  creates an account, which agents may not do. A human should run that drill.
- **`main.bicep` was only compiled** (`az bicep build`, exit 0); it was not deployed. The retention policy and
  the `Continuous30Days` tier are untested against Azure.
- **Emulator caveat:** the vnext-preview emulator is not real Cosmos. Unique-key and batch behaviour on the
  `invoices` container were not exercised beyond plain upserts.
- **Nothing runs the export on a schedule yet**, and nothing uploads the archive to `records-archive`. Until a
  scheduled job does, there is no eight-year copy; only the 30-day PITR exists.

## Decisions / needs a human

   Storage Blob write on `records-archive`; credentials are not available to me (see `docs/platform-identity.md`).
2. Confirm 8 years with the tax adviser, then **lock** the retention policy (irreversible).

## Reproduce
```bash
docker ps --filter name=rs-d3-scratch-cosmos        # local emulator on :18081
EP=http://localhost:18081  EK=<public emulator key>
SCRATCH_COSMOS_ENDPOINT=$EP SCRATCH_COSMOS_KEY=$EK SCRATCH_COSMOS_DATABASE_ID=d3-source \
  npx ts-node --transpile-only scripts/backup/seedScratchSource.ts 50
COSMOS_DB_ENDPOINT=$EP COSMOS_DB_KEY=$EK COSMOS_DB_DATABASE_ID=d3-source \
  npx ts-node --transpile-only scripts/backup/export.ts /tmp/d3/archive
RESTORE_COSMOS_ENDPOINT=$EP RESTORE_COSMOS_KEY=$EK RESTORE_COSMOS_DATABASE_ID=d3-restore-scratch \
  npx ts-node --transpile-only scripts/backup/restore.ts /tmp/d3/archive
```
