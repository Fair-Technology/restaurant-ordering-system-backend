# B2 — Order stays PLACED on a permission/config capture failure

## Change
- `acceptPlacedOrder.ts`: on a capture error that `diagnoseStripeError` classes `permission_or_config`, the capture claim is cleared, `captureConfigFailure {at, attempts}` is written, the order stays `PLACED`, and it returns the new `PAYMENT_CONFIG_UNAVAILABLE_ERROR` (CONFLICT). Card declines and all other non-retryable errors still take the old reject-and-release path (`payment_failed`) — unchanged.
- `executeProcessOrderTimers.ts`: at `autoRejectAt`, an order carrying the marker is rejected with new reason `payment_unavailable` (not `no_response`), the authorization is released as before, and `recordMissedOrder` is skipped.
- New reason `payment_unavailable`: `RejectReason`, bilingual non-blaming email sentence, customer DTO known reasons, swagger enum (swagger.json regenerated by `npm run build`).
- `executeHandlePaymentAuthorized.ts`: now matches via `WAITING_PAYMENT_ERRORS` (both waiting errors) so the diner still gets the "received" email.
- No new order status; storefront copy untouched (C1).
- Marker is dropped on a later successful accept (`withoutClaim`).
- Runbook: `docs/runbook-stripe-key-fault.md`.

## Bounded wait
`autoRejectAt` is set for every non-scheduled order at creation (and at queue entry for scheduled ones); the existing timer rejects at that time regardless of the marker and releases the authorization. Test "a key that is never fixed…" runs three failing minutes then the timeout and asserts `REJECTED`, `payment_unavailable`, `releaseAuthorization` called, payment `canceled`, `recordMissedOrder` not called.

## Tests
`npm run build` and `npm test` pass (172 files, 1579 tests). The pinned test at `executeProcessOrderTimers.test.ts` was rewritten to assert PLACED for permission errors and REJECTED/`payment_failed` for a card decline; added: never-fixed-key timeout, fixed-key recovery, and the handle-payment-authorized waiting case.
